```

■ 実際に納品したもの

・建設業のお客様向け 日報と経理を1つにしたWebアプリ
　自動テスト362件を付けて納品しました。
　テストは変更のたびに自動で実行され、本物のデータベースに対する結合テストまで走ります。
　あわせて、テスト仕様書・手動テスト手順書・本番公開チェックリストをお渡ししています。

・勤怠管理Webアプリ
　タブレットでの打刻に対応し、通信が切れている間の打刻は端末内に貯めて、
　つながったときに送る作りにしています。

・補助金の申請書類を一括生成するツール
　CSVを1回取り込むと、見積書一式・比較整理表・取得財産管理台帳など6種類の書類が出ます。
　Windows / Mac / Linux の3つの環境で同じ書類が出ることを自動で突き合わせて確認しています。
　お客様にお渡しする検証手順書つきです。

いずれもお客様名は伏せています。


■ 特徴：自動テストを付けて納品します

個人への発注でテストが付かないのは、短期的には安く速いからです。
差が出るのは半年後、1年後に機能を足すときです。

テストが無いと、1か所直すたびに全機能を手で確認し直すことになります。
その確認は毎回発生し、そのたびに費用と時間がかかります。
最初にテストを書いておけば、その確認は自動になります。

テストは「品質が高い」ことの証明ではなく、
「あとから直せる」ことの担保だと考えています。


■ 開発が速い理由（安い理由ではありません）

AIによる開発支援（Claude Code）を日常的に使っています。
上記の建設業向けアプリは実作業10人日、勤怠管理アプリは実作業5人日で納品しました。
一般的な見積もりでは、それぞれ90〜100人日、45〜50人日の規模にあたる内容です。

これはテストや設計を省いた結果ではありません。上に書いたとおりテストは付いています。

そのため、価格は「かかった人日」ではなく「何が納品されるか」で決めています。
早く出せることは、値引きの理由ではなく、着手から使い始めるまでが短いという価値です。


■ 進め方

1. 無料相談（30〜60分・オンライン）
　　いまどうやって業務を回しているか、何が一番つらいかをうかがいます

2. 要件整理とお見積もり（無料）
　　作るもの・作らないもの・金額・期間を書面にしてお出しします
　　ここで断っていただいて構いません

3. 開発
　　2週間ごとに、実際に動く画面をお見せします
　　「思っていたものと違う」を最後まで持ち越さないためです

4. 納品
　　ソースコード、自動テスト、操作手順書をお渡しします
　　ソースコードはお客様にお渡ししますので、他の開発者に引き継ぐこともできます


■ ご相談いただける業務の例

・Excelで管理している日報・作業報告を、スマホから入力できるようにしたい
・勤怠の集計を毎月手作業でやっている

・受注や在庫の管理が、担当者の頭の中にしかない

自社で実験用に作っているサービスには、テストを書いていないものがあります。
お客様の業務が乗るものにはテストを付け、自分の実験台には付けない、という運用にしています。
方針として決めていることなので、隠さずに書いておきます。
```
